# WooriLog

Android 전용 가족 건강 기록 앱입니다. 현재는 회원가입 없이 기기 사용자를 관리자로 취급하며, SQLite에 가족과 건강 기록을 저장합니다.

## 실행

Node 24 LTS와 npm을 사용합니다. nvm을 사용한다면 이 폴더에서 다음을 실행합니다.

```sh
nvm use
npm ci
npm start
```

설치된 호환 Expo Go 또는 개발 앱에서 실행합니다. `npm run android`는 연결된 Android의 실행을 시도하는 명령이며 APK를 빌드하지 않습니다. 네이티브 실행 환경이 없으면 별도로 준비해야 합니다.

현재 앱 아이콘은 기본 템플릿 이미지입니다. Android 패키지 ID와 EAS 프로젝트는 아직 지정하지 않았습니다.

## 현재 구현

- 첫 실행 시 가족 이름 설정. 로그인·계정 생성은 없습니다.
- 하단 메뉴: 달력 / 홈 리포트 / 설정. 기본 진입 화면은 홈 리포트입니다.
- 홈 리포트: 전체 기간 영역별 숫자 통계, 모든 구성원의 사람 그림 카드를 좌우로 탐색합니다. 영역별 색 농도는 해당 구성원 안에서의 상대 기록 수를 나타냅니다.
- 월별 달력: 가족 색상과 아픈 영역을 날짜 칸에 표시하고, 날짜를 선택하면 원본 기록 전체를 봅니다.
- 설정: 로컬 관리자 프로필, 가족 구성원 관리, 준비 중인 초대 UI.
- 가족 구성원 추가·이름 수정·8색 팔레트 선택. 기록이 없으면 삭제하고 있으면 보관합니다.
- 기존 DB는 v2로 갱신하여 기록을 보존하면서 구성원 색상을 추가합니다.
- 기록 시작 → 가족 선택 → 색상으로 구분한 몸 그림에서 영역 하나 선택 → 증상 입력 및 저장.
- 건강 기록 목록·문자열 검색·증상 수정·삭제.
- 보관한 구성원의 기존 기록 유지. 새 기록 대상에서는 제외합니다.

상세 폼은 저장 확인을 위한 최소 입력이며, 본격적인 상세 UI·질병·경과·아픔 묶음·기간 필터 등 리포트 고도화는 후속 작업입니다. 현재 기록 수를 발병 횟수로 해석하지 않습니다.

## 데이터 구조와 후속 전환

- `src/data/schema.ts`: 가족·구성원·건강 기록 테이블, 제약조건, DB 버전 초기화.
- `src/data/store.ts`: 화면에서 호출하는 비동기 저장·조회 함수.
- `src/data/context.tsx`: 앱 DB 연결 및 초기화 오류 처리.
- `src/app`: Expo Router 화면.
- `tests/store.test.ts`: 실제 SQLite를 사용하는 저장소 검증.

데이터는 기기의 `woorilog.db`에 저장하며 일반적인 앱 재실행 후에도 유지됩니다. 앱 삭제·앱 데이터 초기화 시 유실될 수 있습니다. 개발 데이터 유실을 허용한 범위에 따라 백업·복원은 구현하지 않았습니다.

Supabase 연동, 이메일·Google 로그인, 초대 코드, 공유, 사용자별 권한은 보류합니다. 로컬 관리자 처리는 인증이나 서버 권한 검증이 아닙니다. Supabase 전환 시 개발 데이터를 초기화하고 저장 함수와 서버 스키마·권한을 구현합니다. 계정과 기록 대상 구성원은 별도로 설계합니다.

## 검증

```sh
npm run check
npx expo-doctor
npx expo export --platform android
```

- 타입 검사·ESLint·SQLite 및 달력·집계 테스트 10개 통과.
- Expo Doctor 21/21 통과.
- Android JS/Hermes 번들 생성 성공. APK/AAB 생성과는 별개입니다.
- SQLite 테스트는 Node의 실제 SQLite에 동일한 저장 함수와 SQL을 실행합니다. Expo Android 네이티브 모듈이나 터치 UI를 직접 검증하지는 않습니다.
- 연결된 Android 기기가 없어 실기기 확인은 미수행입니다.
- `npm audit`: 중간 등급 13건, 높음·치명적 0건. `uuid`/`xcode`와 `decode-uri-component`/`query-string`을 통한 Expo 의존성 경고입니다. 자동 해결안이 Expo·Router의 주요 버전 다운그레이드를 제안하므로 강제 적용하지 않았습니다.

## 실기기 확인 순서

1. 가족 생성 및 구성원 2명 등록.
2. 홈에서 기록 시작 후 구성원 선택.
3. 머리·몸통·좌우 팔과 다리를 눌러 각각 3개 그룹으로 선택되는지 확인.
4. 상세 입력 저장 후 홈 요약과 건강 기록 목록 확인.
5. 이름 및 건강 기록 수정, 기록 검색·삭제 확인.
6. 기록 있는 구성원을 보관하고 이력이 남아 있으며 새 기록 선택에서는 제외되는지 확인.
7. 앱을 완전히 종료한 뒤 재실행하여 기록 보존 확인.
8. 하단 메뉴가 달력 / 홈 리포트 / 설정 순서이고 홈이 기본 화면인지 확인.
9. 가족 색상 변경 후 달력으로 돌아왔을 때 해당 색상이 반영되는지 확인.
10. 같은 날짜의 복수 가족·영역과 +N 표시, 날짜 선택 후 전체 기록 표시 확인.
11. 좌우 카드 넘김, 기록 없는 구성원, 보관 구성원, 영역별 색 농도 확인.
12. 설정의 로컬 관리자 표시 및 초대 준비 중 안내 확인.

기획과 남은 결정 사항은 [기획안](docs/기획.md)을 기준으로 합니다.
